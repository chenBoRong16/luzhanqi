## 2. 做法

### 2.1 爆破（B1、B2）

在 `legalMoves` 的爆破判斷裡改：
- **範圍（B1，已試做）**：
  - 目標要在工兵的公路鄰居裡。用 `roadNbrs`，已經會略過斷橋。
  - 或者在鐵路上相鄰一格。用 `V.railAdj[from]`。
- **對象（B2）**：
  - 拿掉「對方半場」這個條件。
  - 改成：防護格、沒被炸毀、裡面沒有自己的棋。
  - 工兵自己站的格子不算：裡面有工兵自己，本來就排除。
  - 我方半場空的防護格也能炸，不另設例外。
- 爆破的結果不變：只有那一格，裡面的棋不動，工兵翻成明棋。

### 2.2 防空炮改用視線（C2）

- **新增共用函式** `sightCells(S, n, dist)`：回傳從 n 看得到的格子。
  - 沿公路距離在 dist 以內的格子都算，目標在平原上時距離多 1。
  - 隱蔽格（森林、村莊）看不到。
  - 雷達站改用同一個函式，結果和現在相同（回歸會驗證）。
- **擊落判斷**：
  - 現在是「落點和防空炮公路相鄰」。
  - 改成「落點在任一顆對方防空炮的 `sightCells(…, 1)` 裡」。
  - 落點只會是一般格或平原，所以實際效果是：落點在平原上時，距離 2 也會被擊落。

### 2.3 偵察的戰報

- **我方偵察**：「我方偵察 我方 1列4欄 → 對方 1列4欄 的師長；兩顆都翻成明棋」。
- **對方偵察**：「敵方偵察 對方 1列4欄 → 我方 1列4欄 的師長；兩顆都翻成明棋」。
  - 被偵察的是自己的棋，寫出名字不會洩漏資訊。
- 位置用 `LZ.posText`。這個函式在 `record.js` 裡；引擎要用，就在 `engine.js` 加一個同寫法的小函式，免得引擎依賴 `record.js` 的載入順序。

### 2.4 舊棋譜相容

| 隱藏開關 | 預設 | 舊棋譜（沒有這個開關）|
|---|---|---|
| `blastFar`：沿鐵路遠距爆破 | 關 | 開 |
| `blastAny`：任何半場都能炸 | 開 | 關 |
| `aaSight`：防空炮用視線 | 開 | 關 |

- `parseRecord` 補上沒有的開關，做法同上次的 `blastFar`。
- 只有大翻新後（v3）的棋譜才補；大翻新前的棋譜照原本的方式重播。

### 2.5 AI：工兵推進（平衡）

- 在 `ai.js` 給工兵的「移動」加分：走到的格子和一個「裡面有敵棋、沒被炸毀」的防護格相鄰時加分。
  - 分數依那顆敵棋的推測價值，乘一個係數。
  - 扣掉落點的危險度，沿用現有的 `danger` 計算。
- 「清空可動棋」個性也用同一套，加分再高一點。
- 係數先用小規模統計挑，再跑全部地圖驗收。

### 2.6 文件（C1、C4、C5、C10）

- **C1**：附錄加一列「行營開局要空，碉堡可以放棋」，理由：行營是進攻途中的中繼營地，開戰後才進駐；碉堡平時就有守軍。
- **C4**：地雷、炸彈的擺放限制補上現實理由，取代「傳統規則」。
- **C5**：坦克的三條限制合併成一句。
- **C10**：附錄補一句雷達站不能移動的理由。
- **爆破與防空炮**：規則照 §2.1、§2.2 改寫。遊戲內的規則頁同步改。

## 3. 測試

- **爆破**：
  - 隔著鐵路好幾格不能炸；過橋相鄰可以炸；斷橋後不能炸。
  - 可以炸我方半場被敵棋佔住的行營。
  - 有自己棋的防護格不能炸；工兵不能炸自己站的那一格。
- **防空炮**：
  - 落點在平原、距離 2：被擊落。
  - 落點在一般格、距離 2：沒事。
  - 相鄰時照舊被擊落。
- **雷達站**：改用 `sightCells` 後，結果和改之前相同。
- **舊棋譜**：三個開關都補對。
- **戰報**：偵察的文字。
- **平衡**：全部地圖、兩個版本各跑 60 盤，合格條件同規格 §5。
  - 擴充版回歸必定改變，驗收後重錄基準。
  - 原版回歸要一致。
- **瀏覽器實測**：
  - 爆破後的金框。
  - 偵察的戰報與金框。
  - 只在相鄰格出現的「爆破」標籤。
  - 規則頁文字。
  - 主控台沒有錯誤。
