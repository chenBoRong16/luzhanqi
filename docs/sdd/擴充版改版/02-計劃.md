## 4. 每檔責任

| 檔案 | 責任 |
|---|---|
| `shared/expanded-base.js` | `LZ.expandedConfig({ level })` 回傳完整 config：盤面、棋子、規則表、兵力、地形座標、依規則組產生的規則說明。level 0 不含 `bunker`、`sniper` |
| `擴充版-*/config.js` | 呼叫 `expandedConfig`，加上 `key`、`title`、預設佈局 |
| `shared/engine.js` | `buildVariant(cfg, rules)`、`resolveAt`、新走法與新動作、雷達、森林、作弊旗標、違規佈局處理、棋譜和統計的掛鉤。**新行為全部掛在 `V.rule.xxx` 或 `S.cheat.xxx` 上；原版沒有規則開關，作弊預設全關，所以行為不變** |
| `shared/layout.js` | 佈局檔加上 `rules`、`illegal`；`variant: "expanded"` 視為擴充版-0；檢查時可選擇是否寬鬆（無視佈局條件） |
| `shared/record.js` | 棋譜的建立和解析；複盤：用開局佈局、規則組、作弊旗標重建狀態，一步步套用 `applyMove`。支援跳到任一手 |
| `shared/ai.js` | 對撞改用 `resolveAt`；狙擊和炸橋的評分；考慮森林停一回合；違規佈局時不靠開局位置推理 |
| `shared/ui.js` | 作弊選單逐項開關、規則面板（只有擴充版）、地形與斷橋、新動作的標示、複盤列、統計面板、棋譜匯入匯出 |
| `tests/test.js` | 新規則、新地形、作弊開關、違規佈局、佈局檔和棋譜來回 |
| `tests/stats.js` | 兩個擴充版各 60 盤：先手勝率、和棋率、各機制的每盤次數 |

## 5. 機關怎麼接

| 項目 | 接在哪 | 作法 |
|---|---|---|
| 規則組 | `buildVariant(cfg, rules)` | 依開關過濾棋種和地形，產生 `V.rule`。規則改變就重建 variant。檔案一律存棋名，不存編號 |
| 對撞 | `resolveAt(S, A, D, toNode)` | 包住原本的 `resolve`，處理碉堡加級、坦克對雷、防空炮對傘兵、雷達被攻擊 |
| 碉堡加級 | `V.rankUp[t]` | 建 variant 時算出每種棋「往上一格」的等級 |
| 空降限制 | `movesFor` 的傘兵分支 | 排除對方防空炮公路相鄰的格子；落地時設「翻倒」 |
| 坦克轉彎 | `movesFor` 的坦克分支 | 兩步正交 BFS，第一步必須是空格 |
| 偵察距離 2 | `movesFor` 的偵察分支 | 公路 BFS 深度 2；排除森林裡的棋 |
| 狙擊 | 新動作 `snipe` | 目標條件同坦克直線兩格。推理：失敗代表目標至少是營長，或是炸彈、地雷、軍旗 |
| 炸橋 | 新動作 `blow`（目標格＝橋的另一頭），記錄在 `S.broken` | 走公路時略過斷掉的橋 |
| 雷達 | `updateRadar(S)` | 開局和每一手之後呼叫，把相鄰敵棋設為明棋 |
| 翻倒（森林、空降） | 棋子欄位 `stunned`（布林） | 走進森林或空降落地時設為 true；`legalMoves` 檢查。**用布林而不用手數**，和實體棋盤的「橫放」一一對應。<br>扶正的時機：A 方每走完一手，先把「這手開始前就已翻倒」的 A 方棋扶正，再處理這手新產生的翻倒。這樣剛翻倒的棋會停過 A 方完整的下一回合 |
| 全部翻倒（C15） | `checkStuck` | 判負前先看：只要有翻倒的棋，就改成跳過這回合（扶正後換對方），並記入棋譜 |
| 明棋 | 棋子欄位 `faceUp`（布林） | 偵察、雷達、司令陣亡亮旗、狙擊失敗時設為 true，同時把雙方推理設為確定。介面畫成明棋 |
| 判和計數 | 既有的 `S.quiet` | 介面在盤邊畫計數軌 |
| 推理 | `filterMask` 改用 `resolveAt` | 碉堡、防空、坦克對雷的推理就自動成立 |
| 作弊逐項開關 | `S.cheat = { infinite, reveal, feed, add, del, drag, swap, ignorePlacement }` | 介面依旗標決定點擊和拖曳的意義；交換、悔棋按鈕在開關打開時才出現 |
| 無視佈局條件 | `validateSide`、`validateGrid` 加 `loose` 參數；記錄 `S.illegal[side]` | 違規的那一方，開局推理設為「什麼都有可能」（C10）。奪到任一面軍旗就勝；沒有軍旗就只看「無棋可動」（C11）。現有引擎已經是這個行為，只需補測試 |
| 棋譜 | `S.record` | `applyMove` 和作弊函式都寫入；悔棋時截斷。只是附加記錄，不改變走法，所以原版回歸不受影響 |
| 統計 | `S.stats` | `applyMove` 內累加 |
| 實體相容 | 規則狀態只允許：位置、`faceUp`、`stunned`、`dropUsed`、`S.broken`、`S.quiet` | T11 抽查時對照規格 §1b，用 grep 確認引擎沒有其他規則狀態（推理、棋譜、統計、作弊旗標屬於介面或紀錄，不算規則狀態） |

## 7. 風險

- **AI 變慢**：雷達、狙擊、坦克 BFS 會增加計算量。擴充版一手超過 1 秒，就把威脅快取延伸到新動作。
- **炸橋 AI 可能很少用**：先用簡單規則評分（對方大子在橋對岸、我方守不住才炸）。用量不夠就在 T7 調整。
- **模擬耗時**：T9、T10 兩版合計約 60～80 分鐘，放在背景跑，期間繼續做文件和介面抽查。
