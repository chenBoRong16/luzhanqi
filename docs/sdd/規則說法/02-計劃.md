# 規則說法：計劃（SDD 第 2 步）

狀態：2026-10-04。照 `01-規格.md` §1 的 A～F。不改走法。不試作：這些句子都接在現有的規則開關上，開關一改就會整頁重載。

開工（第 3 步）前先備份到 `_備份/14-規則說法前/`，只複製會改的檔。

## 1. 改哪些檔

| 檔 | 責任 | 規格 |
|---|---|---|
| `index.html` | 首頁兩張卡片的靜態句子 | A、B |
| `shared/expanded-base.js` 的 `rulesHtml` | 遊戲內規則頁。已有 `on(id)`，句子跟目前的規則組走。改規則會 `mountApp` 重載，所以關掉加成後會換成舊說法 | C、D、F |
| `shared/board-draw.js` 的 `terrainLegendHtml` | 地形圖例。對局地圖卡、規則頁、地圖編輯器都呼叫它，只改這一處 | E |
| `docs/rules-expanded-0.md` | 實體配件表的判和那一列 | F |

不改：`engine.js`、`ui.js`、`editor.js`、`rules-expanded-1.md`、測試。擴充版-1 的文件已寫「取代打不到」和「狙擊命中歸零」。

## 2. 各檔怎麼接

### 2.1 首頁（A、B）

- 擴充版-0 的棋子清單：「偵察」改成「偵察兵」。
- 擴充版-1 拿掉「碉堡防守時高一級」。改成一句防守值：森林、村莊、行營 +1，碉堡 +2，沼澤 −1。狙擊手那條留著。

### 2.2 遊戲內規則頁（C、D、F）

都在 `rulesHtml`，用已經有的 `on("terrainDef")`、`on("sniper")`、`on("aa")`。

- **狙擊**（只在有狙擊手時出現）：`terrainDef` 關著寫「隱蔽格、防護格不能狙擊」。開著改成「隱蔽格不能狙擊；行營、碉堡可以，用加成後的等級和營長比」。
- **爆破**：`terrainDef` 開著時，拿掉「打不到」。改成點有對方棋的防護格時可以攻擊或爆破，攻擊用加成後的等級。關著維持「打不到，只能爆破」。
- **判和歸零**：底句是「攻擊（不論勝負）」。有狙擊手才加「狙擊命中」，有防空炮才加「傘兵被擊落」。擴充版-0 預設沒有狙擊手，就不會出現「狙擊」。
- 同一函式裡偵察那句的「偵察自己」改成「偵察兵」。棋名早已改了，這句還在用舊名。

### 2.3 地形圖例（E）

`LEGEND` 維持加成關著時的句子（行營、碉堡仍是「打不到」）。`terrainLegendHtml` 看到 `V.rule.terrainDef` 時，只改這五格的規則句：

| 地形 | 加在原句上 |
|---|---|
| 森林、村莊 | 防守 +1 |
| 行營 | 改成打得到，防守 +1，仍可爆破 |
| 碉堡 | 改成打得到，防守 +2，仍可爆破 |
| 沼澤 | 防守 −1 |

平原、高山、鐵路不加。編輯器不用另改，它本來就呼叫這個函式；擴充版-0 沒有這條開關，圖例維持「打不到」。

### 2.4 擴充版-0 文件（F）

實體配件表的判和列：拿掉「狙擊」，改成攻擊（不論勝負）或傘兵被擊落就歸零。地形一覽裡的「打不到」是擴充版-0 的真規則，留著。
